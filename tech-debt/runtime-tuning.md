# Старт, память и образ API не настраивались

API публикуется и запускается с настройками .NET по умолчанию: `dotnet publish` без
идентификатора среды, образ `mcr.microsoft.com/dotnet/aspnet:10.0`
(`src/PetTemplate.Api/Dockerfile`), серверный сборщик мусора. Пока ничего из этого не мешает:
контейнер перезапускается только на деплое. Записано, чтобы при первой жалобе на старт,
память или размер образа было с чего начать.

## Native AOT — не делаем

MVC-контроллеры, EF Core на Npgsql, Swashbuckle, Qdrant.Client, OpenAI SDK —
рефлексия, под AOT не рассчитаны. Чинить внешние библиотеки ради выигрыша, который
не нужен, не будем; пиковая производительность от AOT не растёт.

## Что уже есть само

- **TieredPGO** включён по умолчанию с .NET 8 — флаг в проекте ничего не добавит.
- **Сборщик мусора.** Серверный GC в .NET 9+ идёт с DATAS (динамическая подстройка числа
  куч и их размера под нагрузку), а потолок памяти контейнера (`--memory` в `IaC/run-api.sh`)
  GC видит и сам: «куча на каждое ядро» на машине в два ядра уже не держит лишнего.
  `DOTNET_GCHeapHardLimit` и workstation GC — только по замеру, если API упрётся в потолок.

## Что рассмотреть, когда заболит старт

1. **ReadyToRun** — `<PublishReadyToRun>true</PublishReadyToRun>` делает публикацию зависимой
   от идентификатора среды: без `-r` SDK берёт среду машины сборки, а `publish-api.yml` собирает
   отдельным шагом и публикует `--no-build` — `-r linux-x64` нужен в обоих шагах, иначе
   публикация не найдёт сборку под среду. Это правка workflow, а не проекта. Быстрее старт,
   крупнее публикация; старт API бывает только на выкатке, поэтому сейчас не делаем.
2. **Chiseled-образ** — `aspnet:10.0-noble-chiseled`: без оболочки (не от root API работает
   уже и так — `USER $APP_UID`, спец. infrastructure, 6).
   Тогда сломаются `HEALTHCHECK` образа (он на `bash` и `/dev/tcp`) и `docker exec … sh`:
   проверку здоровья придётся нести своим бинарником или убрать из образа, оставив ожидание
   `/health` в `IaC/run-api.sh`.
