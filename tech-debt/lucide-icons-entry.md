# Иконки lucide — второй копией модуля

Замер `--stats-json` показал: `lucide-angular` поставляется одним
файлом `fesm2020/lucide-angular.mjs` (компонент и все иконки), а esbuild режет бандл по файлам,
а не по частям файла. Оболочка (меню, шапка) берёт из него компонент — и все иконки, которые
где-либо импортированы из `'lucide-angular'`, ложатся в тот же чанк initial, хотя
`provideIcons` регистрирует их в ленивом экране. Иконки экранов пространства и ассистента
стоили так ≈2.5 КБ начального бандла.

Решение: экраны берут иконки из второго входа пакета, `lucide-angular/src/icons`
(`fesm2020/lucide-angular-src-icons.mjs`): этот файл initial не трогает, и его иконки уходят
общим ленивым чанком. Оболочка и иконки, которые она уже показывает (`Users`, `LogOut`), —
по-прежнему из `'lucide-angular'`: они и так в initial, вторая копия их данных не нужна.
Правило — в `src/PetTemplate.Web/agents.md`, «Иконки».

Цена:

- второй вход — **полная копия** пакета, с компонентом. В боевой сборке лишнее вычищает
  оптимизатор (в ленивый чанк уходят только данные иконок), а в разработке и тестах файл
  выполняется целиком — Angular пишет в консоль предупреждение `NG0912` о двух
  `LucideAngularComponent` с одним селектором. Оно безвредно: рисует компонент из
  `'lucide-angular'`, у второй копии нет ни одного использования;
- иконки всех ленивых экранов лежат одним общим ленивым чанком (сейчас ≈2.5 КБ), а не каждая
  в своём экране — первый открытый экран с иконками грузит их все.

**Когда возвращаться** — когда пакет lucide для Angular начнёт поставлять иконки отдельными
модулями (по файлу на иконку): тогда импорт `'lucide-angular/src/icons'` меняется на поштучный,
и `NG0912` уходит.
