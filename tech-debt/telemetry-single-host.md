# Телеметрия рассчитана на одну машину

Всё живёт на одной виртуалке и в одной докер-сети `nginx-proxy-man`: API, коллектор
OTLP, Prometheus, Tempo и Grafana (`IaC/DEPLOYMENT.md`, «Телеметрия: что показывает Grafana»).
API шлёт в коллектор по имени контейнера
(`otelcollectorcontainer:4317` в `publish-api.yml` и `rollback-api.yml`), коллектор — в Prometheus
и Tempo тоже по именам. Так же, по именам, Prometheus сам забирает метрики у экспортёров
(`postgres-exporter`, `node-exporter`, `cadvisor`; с поиском — и у Qdrant). Портов наружу нет, и своей
аутентификации ни у кого из них нет: защищает только то, что снаружи до них не дотянуться.

Пока машина одна, этого хватает. При переезде на несколько серверов это перестаёт
работать: имена контейнеров не видны с другой машины, а открыть порты Prometheus и
Tempo без аутентификации нельзя.

## Что сделать при переезде

- **Коллектор на каждой машине с API** — агентом рядом с приложением. API по-прежнему шлёт
  на локальный адрес, а агент пересылает дальше и держит буфер, пока хранилище недоступно.
  `node-exporter` и `cadvisor` тоже ставятся на каждую машину, а забирать их метрики
  должен агент — центральный Prometheus до них не дотянется.
- **Prometheus, Tempo и Grafana — на отдельной машине мониторинга**, чтобы нагрузка на
  хранилище не отнимала память у API и базы, а падение API-машины не уносило её метрики.
- **Сеть между машинами** — частная сеть провайдера или VPN (WireGuard). Агенты шлют на
  центральный коллектор по TLS с токеном или клиентским сертификатом; порты Prometheus и
  Tempo наружу не открываются.
- **Своя докер-сеть для телеметрии** вместо общей `nginx-proxy-man`: сейчас любой
  контейнер этой сети может писать в Prometheus и читать из него. Отдельная сеть уже есть
  только у шлюза Grafana (`grafana-gateway`, адреса nginx и Grafana закреплены).
